## 1. 网络与部署形态（回答「上位机地址是什么」）

平台档案接口 `archivesMan/getDateById` 返回的 `localhostIp`（字段语义：**本体IP地址**）
即为集成商登记的上位机地址。实测该值 **与业务平台主机地址同一个**，即：

```
上位机 = 业务平台一体机 = 同一台 x86 工控机
  ├── :8888   业务平台 HTTP + WebSocket（Vue 前端 / OpenAPI / STOMP-over-WS / 运控 WS）
  ├── :22     SSH
  ├── :1883   ActiveMQ — MQTT 连接器
  ├── :5672   ActiveMQ — AMQP 连接器   ← 旧版本文档误记为「RabbitMQ」，已更正
  ├── :61613~61616  ActiveMQ 原生（61613 STOMP / 61614 WS / 61616 OpenWire）
  ├── :8161   ActiveMQ Web 控制台      ← 🔴 见 §5 安全提示
  ├── :9000 / :9091  MinIO / MinIO 控制台  ← ⚠️ 见 §8 许可风险
  ├── :9011   Docker 服务
  ├── :6379   Redis
  └── :3306   MySQL
```

> **消息中间件已定性：ActiveMQ**（2026-08-10，据集成商《端口映射一览表》）。
> 端口指纹完全吻合 ActiveMQ 默认传输连接器组（1883 MQTT / 5672 AMQP / 61613 STOMP /
> 61614 WS / 61616 OpenWire / 8161 控制台）。这解释了 §3.4 逆向到的 `/robot/mq/`
> ——那是 ActiveMQ 的 WS 连接器经 `8888` 反向代理暴露的。

要点：

1. **本项目实际取值不写入本仓库**（脱敏准则 6），从 `configs/dog/*.json` 与
   `archivesMan` 档案读取。下文一律以 `<平台主机>` 指代。
2. **宇树内网（`192.168.123.0/24`，B2 板载算力所在网段）从办公网不可路由**，
   `7400/7401`（DDS discovery）在 `<平台主机>` 上未开放。
   → **DDS 受阻不只是集成商政策问题，是网络拓扑的硬约束。**
      要走 DDS，必须先落地跨网段路由或在上位机内部署，两者都需集成商书面同意。
3. 手册 §5.3 / §5.9 出现的 `192.168.123.76` / `192.168.123.12` 是**在线云端版文档示例**，
   非本现场取值；档案 `configJson` 内 `light.ip` 字段与其 `rtsp_url` 网段亦不一致
   （字段陈旧，**以 `rtsp_url` 为准**）。
4. **部署形态判定（v2-E7 已闭合）**：本现场为 **离线一体机（`8888` 本体服务）**，
   登录走 JSON + `tuopushi_edge_token` 头。集成商端口表把服务明确分成三档，可据此自证：

   | 档 | 服务 | 端口 | 本现场 |
   |---|---|---|---|
   | 仅云端 | 云端服务 / 云端机器人(单点登录) / 云控 / 网关 | `8001` / `8885` / `18201` / `8070` | ❌ 不适用 |
   | 仅离线 | **本体服务** | **`8888`** | ✅ **本现场** |
   | 云端+离线 | Docker / ActiveMQ / MinIO / MySQL / Redis | 见上 | ✅ 共用 |
   | 流媒体 | CVR / CVR-GB | `18000` / `15060`+`4443`+`18319`+`19350`+**`50000-50070`+`30000-30070`** | ⚠️ 见 §8；2026-08-13 已从 1000+ 收到 142 |

   → **v2-E7「部署形态与写权限（云端 :8001 vs 离线 :8888）」不必再问厂商**，本表即答案。

5. ⚠️ **CVR-GB 动态段（2026-08-13 修订）**：更新版清单为 `50000-50070` + `30000-30070`（约 142 口，TCP+UDP），
   另加固定口 `15060` / `4443` / `18319` / `19350`；CVR 本体 `18000`。
   旧口径 `50000-50500`+`30000-30500`（1000+）**作废**。集成商解释为国标点播随机分配、
   「一路视频 4 口 × 一狗 4 路」。我司流媒体侧认为端口应复用、用推流地址区分。
   **本场景实际占用以 E7 实测为准，禁止采信公式或清单区间。**
   这仍是 §8 端口收敛争议的焦点，且与我方视频取流相关。

## 3. 前端逆向补充（未文档化，⚠️ 无厂商契约保证）

来源：`<平台主机>:8888` 的 Vue 打包产物（`main-*.js` + 懒加载 chunk）。
**这些接口没有官方文档，随版本升级可能变更，接入前必须让厂商书面确认。**

### 3.1 连续运控：WebSocket `/edg`

- 端点：`ws(s)://<平台主机>:8888/edg`　（实测握手返回 `101`，服务存活）
- 心跳：每 **30 s** 发 `{"data":"0000","value":null}`
- 移动指令（**ROS Twist 语义**）：

```jsonc
{
  "robotId": "<robotNum>",
  "data": "move-by-direction",
  "value": {
    "robotId": "<robotNum>",
    "twist": {
      "linear":  { "x": 0.3, "y": 0.0, "z": 0 },   // x 前后, y 横移
      "angular": { "x": 0, "y": 0, "z": 0.0 }      // z 转向
    }
  }
}
```

- 前端默认速度标量 **0.3**（滑条可调），按住方向键时以 **200 ms 周期（5 Hz）重复下发**。
- 松键 / 停止：**下发全零 twist**，前端侧无其它停止手段。
- 键位：`I`=前 `J`=左转 `K`=后 `L`=右转（keyCode 73/74/75/76）。

✅ **2026-08-10 官方确认**：WS 就是运控的正式载体——「控制协议目前没有 http 请求，后面才会补充，
目前是采用 ws 协议发送控制移动指令」。即本节逆向所得**与官方一致**，但**正式协议文档尚未提供**（无兼容承诺）。

✅ **deadman = 0.5 s**（官方）：「发送一次速度指令后，0.5 s 没有收到速度指令会自动停止」。
前端 200 ms 周期因此有 2.5× 裕度。第三方实现的指令周期必须 **< 500 ms**。

> ⚠️ 上文「前端代码中无 deadman 证据」的推断**已被官方答复取代**——deadman 在服务端/机器人侧，
> 前端看不到是正常的。**但实现层级仍未知**（上位机服务 vs 狗底层控制器），
> 这决定「上位机死机时狗会不会停」，必须实测。

⚠️ **服务端不做速度限幅**（官方：「速度上线服务器目前没有做限制」）。
下发多大就执行多大，**客户端限幅是唯一防线**。

⚠️ **当前版本运控不校验控制权**（官方：「最好是获取控制权，目前版本是没加这个逻辑，后续更新后会增加判断逻辑」）。
第三方与 Web 界面**可同时下发**，平台侧无互斥。控制权可在界面右上角第二个图标或「机器人档案-菜单-释放控制」释放。

### 3.2 离散动作：`POST /service/model/action`

请求体 `{ "robotId": "<robotNum>", "type": <int> }`

| `type` | 语义 | 关联 `gait` |
|---|---|---|
| `0` | 下蹲 / 趴下 | — |
| `1` | 站立 | `0` |
| `3` | **急停** | — |
| `5` | 爬坡模式 | `2` |

手册附录 B 明确：**「急停 ≈ 断电」**。即 `type=3` 不是优雅减速停车，
而是切动力（狗会失去支撑）。安全设计中**不可**把它当作常规刹车使用。

✅ **2026-08-10 官方补充**：
- **停止移动 = 下发零速**，「可以调用接口，也可以通过速度指令发送 0」。
  **这就是常规刹车，没有别的中间档。**
- 软件急停「是看底盘的，B1/B2 的只是电机没电，**没有彻底断电的接口**」。
  即 `type=3` 的效果是**电机断电**（非整机断电），狗仍会失去支撑塌落。
- 🔴 **B2 无身高 / 步态能力**：「身高/步态目前只有 B1 才会有用，B2 及其他机器狗没有」。
  下表中 `bodyHeight` 与 `gait` 相关项**在本机（B2）无效**，不要实现。

#### 3.4.1 ⚠️ 头号陷阱：按机器人分发的主题必须拼 SN 后缀

前端 §3.4 常量表里的主题字符串**不是完整目的地**。订阅前会拼 `.<robotNum>`：

```js
subscribeToTopic([`${ROBOT_STATUS}.${robotNum}`, `${ROBOT_SCAN}.${robotNum}`, …])
// → /topic/service_robot_status.<机器人SN>
```

**订裸主题（不带后缀）会静默收到 0 帧，且不返回任何 `ERROR` 帧。**
初次实测正是踩了这个坑，一度误判为「平台没在推送」。
连 `/topic/#` 通配也收不到 —— 该 broker 不按 RabbitMQ `#` 语义匹配，**通配探测不可作为反证**。

| 主题 | 是否需 `.<robotNum>` |
|---|---|
| `service_robot_status` / `_scan` / `_velodyne_base_laser` / `_task_result` / `_map_base64` / `_taskItem` | ✅ **必须** |
| `service_robot_event.>` / `service_robot_alarm.>` / `_obstacle_avoidance_topic` | ❌ 按原样 |

#### 3.4.2 只读订阅实测结论（2026-08-08，已通过）

工具：`tools/topsee_mq_probe.py`（零依赖；帧类型白名单锁死为
`CONNECT`/`SUBSCRIBE`/心跳/`DISCONNECT`，**不具备下发控制指令的能力**）。

| 主题 | 帧率 | 活性校验 |

| `speed` / `rpy` / `motorangle` / `odometer` | 运动量 | |
| `delayTime` / `useCpu` / `useMemory` / `runningTime` / `runningDay` | 健康度 | `delayTime` = **狗↔服务器时延**（官方 2026-08-10），**不是射频信号** |
| `signalStrength` | 蜂窝信号 0–31（31 最强） | 🟡 **承诺月底可测**；现网未检出时默认 0。禁止当运动门禁 |
| `time` | 设备时间（Unix 秒） | ⚠️ **仅秒级分辨率**，2 Hz 下每两帧共用一个值 |
| `connection` | 连接状态 | |

**工程结论**：

1. 🎯 **G4 / G5 彻底解开**。位姿与置信度都能拿到，**完全不依赖 DDS**。
   交接文档「无置信度、无实时位姿接口」的结论**仅对 HTTP 成立**，对 MQ 不成立。
2. ✅ **E4-S（只读影子部署）的数据前提已齐备**：位姿 + 激光 + 点云 + 状态 + 控制权。
3. ⚠️ **2 Hz 只够慢通道**。做影子部署、到点判定、评测足够；
   **不足以支撑 10 Hz 级闭环快通道**，不要拿它当 WAM 控制回路的状态源。
   ✅ 官方称**后续可调至 10 Hz**，但「后面」无时间表——按 2 Hz 设计，升频后再论证放宽。
4. ⚠️ **`time` 秒级分辨率不可用于时序对齐**，必须以本地接收时刻（`t_mono`）为准。
5. ✅ `matchProb` 使人工 `ack_confidence` 可以自动化。
   ✅ **官方明确置信度是参考值、不必 >0.9，视现场环境而定** ——
   本机常态 0.63~0.69 且派单成功，与手册 §4.4.1 的「≥0.9」冲突，**以官方答复 + 实测为准**。
   门禁阈值应做成可配置，不再硬卡 0.9。
