# Wander 铁丝笼真机验证方案与规格偏离申请（2026-07-28）

- 场地：铁丝网围合的笼子，**长条形 11–12m × 4.5–5m**
- 障碍：椅子 ×3 —— 1 张 ~1.5m 高，2 张 ~0.5–0.8m 高
- 配置：`configs/wander-cage.json`
- 依据规格：`docs/design/2026-07-27-wander-explore-design.md`（chmod 444，只读）
- 本次不录制数据；飞行行为确认后再开 `--record`

## 1. 规格偏离申请（需主人/Claude 裁决）

### D-5　巡航带 h_min/h_max：80/200 → 60/130（主人 2026-07-28 裁定）

- 规格 §2.3 定 `h_min_cm=80`，理由「<80cm 进入地效区且容易撞低矮家具」。
- 本场地障碍高 0.5–0.8m。`zone_nearness()` 取深度图 `[0.30, 0.80]` 横带的**中位数**，
  要 `mid > turn_thresh=0.58` 必须让障碍占据该横带过半像素。
  几何估算（Tello 垂直 FOV ≈ 55°，横带覆盖光轴上 11°～下 16.5°）：
  - 飞 0.6m、椅高 0.6m、距 1.5m → 椅子占横带垂直向 ~60%，中位数由椅子主导 ✅
  - 飞 1.2m、同一椅子 → 椅顶落在光轴下 ~22°，出横带，中位数由背景主导 ❌
- 结论：**飞行高度必须 ≤ 障碍高度**，否则矮椅在深度上不可见，撞机风险高于地效风险。
- 下限取 60 而非主人初提的 40：Tello 螺旋桨离地 <0.5m 时地面涡流明显，
  且下视 VPS 在 0.4m 附近定高抖动放大；60cm 已足够看到 0.5m 椅子。
- 上限取 130（主人裁定）。**注意其含义**：巡航带是单向软钳制，不会主动拉回，
  飞机实际高度由起飞后手动压到的高度决定。飘到 110cm 以上时 0.5m 矮椅将退出
  深度横带、检测失效 → 飞行中盯 HUD 高度，超 110 手动按 `F` 压低。

### 场地形状带来的额外约束（11–12m × 4.5–5m 长条）

- 短边仅 4.5–5m，`turn_thresh=0.58` 约在 1–1.5m 触发，横向可飞距离只剩 ~2m。
  粗算一次「遇障→转向→VERIFY→抵达对侧」约 9s，20s 窗口内约 2–3 次遇障转向，
  尚不足 `corner_max_turns=4`，故**首飞仍不预调防打转参数**；若日志出现
  `wander_cornered`，再单独调 `corner_window_s` 或 `corner_max_turns`（一次一个）。
- 起飞点置于长条中段、机头**沿长轴**，给第一段最长的自由行程。
- 椅子沿长轴分散摆放，彼此间距 ≥2m：1.5m 高那张放长轴中段做主障碍，
  两张矮椅分置两侧。避免全部堆在中央形成「家具迷宫」直接触发防打转。

### 已知隐患（本次不改，仅登记）

`WanderPolicy.__init__` 在未注入 `zones_ctrl` 时自建 `AvoidanceController()`，
用的是 `AvoidParams` **dataclass 默认值**，不读 `configs` 的 `avoid` 节。
当前两处 `band_top/band_bottom` 恰好同为 0.30/0.80，不影响本次飞行；
但若标定后需要下移深度横带来适配矮障碍，**改配置无效，必须改代码**（违反规格 §7 坑 #9 阈值单一来源）。
→ 若 Phase 0 标定判定需要调 band，先提工单，不在现场改。

## 2. 场地风险（运维，非软件可解）

1. **铁丝网大概率在单目相对深度里"透明"**：网孔镂空 + 模型看穿到网后远景 → nearness 偏低=开阔。
   规格 §3.3 已把镜子/玻璃/白墙列为必须物理遮蔽，铁丝网同类。
   → Phase 0 实测；不达标即用不透视材料（防尘布/纸板/彩条布）遮蔽至 1.2m 高。
   **禁止**为此给深度管线打补丁（规格 §7 新增坑 #1）。
2. **法拉第笼效应**：2.4GHz 波长 12.5cm，网孔 <6cm 时对 Wi-Fi 有可观衰减。
   → 路由器与 Mac 必须置于笼内；起飞前静态 `ping` 60s 无丢包才允许飞。
3. 笼内空间小 → 遇障转向密集，`corner_window_s=20 / corner_max_turns=4` 可能触发
   `wander_cornered` abort。**首飞保持默认不预调**（调参守则：先看日志再改、一次一个）。
