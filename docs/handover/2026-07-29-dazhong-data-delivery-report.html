4. 对齐保证

  • video.mp4 第 N 帧 ↔ frames.csv 第 N 行，严格 1:1
  • video_frame 从 0 起；frame_id 从 1 起；恒满足 video_frame == frame_id - 1
  • 精确时刻用 t_mono_ms（单调时钟毫秒），不要死信容器 fps

5. frames.csv 字段定义

5.1 索引与媒体

列定义
frame_id帧序号，从 1 起
t_mono_ms相对回合起点的毫秒（对齐基准）
video_frame对应视频帧号，从 0 起
rgb_path当前为空（RGB 在 mp4 内）
depth_path如 depth/000001.npy；无深度则空
has_depth1 / 0
depth_rtt_ms深度推理往返时延（ms）
depth_age_ms该深度相对本帧的滞后（ms）

5.2 位姿 / 遥测（机载）

列定义
yaw_deg pitch_deg roll_deg姿态角（度）
height_cm高度（厘米）
vgx vgy vgz速度估计
bat_pct电量百分比
pad_id pos_x_cm pos_y_cm pos_z_cmmission pad 相关；未识别时常为 -1 / -100

5.3 操控动作（训练核心）

范围 −100 ~ +100，语义同 Tello SDK rc：

列含义正方向
act_roll横滚（左右平移）右
act_pitch俯仰（前后）前
act_throttle油门（升降）上
act_yaw偏航（原地转向）顺时针

ctrl_state：动作来源。

  • 漫游：干净枚举，如 WANDER_CRUISE / WANDER_TURN / WANDER_VERIFY / MANUAL / HOVER
  • 绕飞：常为带遥测的长字符串，筛选用 ctrl_state.startswith('ORBIT')

5.4 感知辅助（非必需）

  • near_left / near_mid / near_right：三区相对近度 0~1，越大越近，逐帧归一化
  • wander_state / wander_event：漫游内部状态与事件；绕飞回合通常为空

6. meta.json 元数据定义

字段含义
episode_id目录名，如 ep_20260727_204010
created落盘时间（ISO，含时区）
record_hz录制频率（当前 10）
drone / sim飞机 IP；是否仿真
camera机型与分辨率
depth深度模型与语义（nearness relative）
scenario场景标签（漫游有 wander_explore）
action_sourcemixed=含人工；avoidance=自动策略
n_framesCSV / 视频帧数
n_depth_frames / depth_grid深度文件数与网格尺寸 [96,128]
frames_manual / frames_auto人工 / 自动帧统计
video.*编解码、CRF、分辨率、对齐说明
t_start_ms / t_end_ms时长边界
battery_start_pct / battery_end_pct起止电量
outcome / abort_reason结局标记
notes策略参数、转向次数等扩展信息
⚠️ outcome: aborted + abort_reason: session_cleanup 不是飞行异常， 只是断连收尾的流程标记。绕飞那份就是这种情况，实际 0 次 abort / danger / lost。

7. 训练侧怎么用（给对方一句）

  1. 读 video.mp4 第 N 帧作为观测
  2. 读 frames.csv 第 N 行的 act_roll/pitch/throttle/yaw 作为动作标签
  3. 用 ctrl_state 区分人工示教与自动策略（需要时可筛 MANUAL / ORBIT / WANDER_*）
  4. depth/ 可忽略；大众训练不依赖深度
