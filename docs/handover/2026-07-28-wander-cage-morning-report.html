3. 数据格式说明（给大众训练侧）

3.1 目录结构

ep_XXXXXXXX_XXXXXX/
├── meta.json      # 回合元数据、参数、结局、wander notes
├── video.mp4      # H.264 / CRF18 / 960×720 / 标称 10 fps
├── frames.csv     # 逐帧表，行号 = 视频帧号（严格 1:1）
├── depth/         # 96×128 nearness .npy（可选；视觉→动作可先忽略）
└── README.md      # 中文可读说明（已随包）

3.2 对齐契约（硬保证）

  • video.mp4 第 N 帧 ↔ frames.csv 第 N 行（本批已校验 match=True）
  • 真实时刻用 t_mono_ms，不要假设严格等间隔 100ms
  • depth_age_ms 诚实记录深度滞后；本批 P95 < 410ms

3.3 动作语义（训练标签）

列含义范围正方向
act_roll横滚 / 左右平移−100…100右
act_pitch俯仰 / 前后−100…100前
act_throttle升降−100…100上
act_yaw偏航−100…100顺时针

建议归一化：action = [roll,pitch,throttle,yaw] / 100.0，与现有 WAM 对接方案中的 vx/vy/vz/wyaw ∈ [-1,1] 一致 （见 docs/handover/2026-07-22-wam-brain-integration-plan.md）。

3.4 必须告知大众的限制

  1. 深度是相对 nearness，逐帧归一化，不是米制深度；大平面/镂空网可能误报「开阔」。
  2. 速度遥测 vgx/vgy/vgz 恒为 0（TT 硬件不报），勿当监督信号。
  3. 位姿 pos_* 仅在 Mission Pad 锁定时可信；笼内长飞多数时刻不可用。
  4. 漫游包含少量 MANUAL 帧：若只要策略动作，请排除 MANUAL/HOVER。
  5. 铁丝网场地：边缘可能「深度透明」，存在贴网后退/danger 片段——边缘数据可保留，但需在 meta 标注场地。
