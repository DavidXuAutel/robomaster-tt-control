## 0. 本次改造改了什么（一句话）

项目重心从「把狗接进 MissionBrain 编排」升级为「**部署闭环**」：

> **服务器当老师 → 边端跑学生模型 → 量化评测（时延/内存/功耗/成功率）→ 独立故障哨兵 → 影子部署 → 受限闭环**。

改造理由：
1. 远程 GPU（cloudflared 隧道 4090）在实时链路里＝延迟污染 + 单点故障，只应做教师与离线标注；
2. 「记录了数据」≠「数据可训练」——丢帧/时钟漂移/动作延迟目前无人自动检查；
3. 让生成式模型直接控 60kg 真狗是错误顺序——必须先有独立于模型的安全哨兵与影子期。

### 0.1 核心铁律

**模型只出提议（proposal），执行权永远在独立哨兵/仲裁层手里；模型进程崩溃，狗必须能停。**

### 0.2 Gate 的两种作用域（本节解决 v3.0 的架构矛盾）

现有 `DogControlArbiter` 的不变量 I3/I4 规定：`MISSION_NAV`（平台慢通道导航中）期间**禁止**发任何运动命令。因此「在原生导航上叠加减速」**不可实现**，明确放弃。ProposalGate 按 Arbiter 状态分两种作用域：

| Arbiter 状态 | Gate 作用域 | Gate 能做的动作 |
|---|---|---|
| `MISSION_NAV`（平台导航中） | **观察者**（shadow） | 只记录裁决 + 告警；风险持续超阈时**只能走任务级停止**（`TopseeNav.cancel()` → `stopTask`，这是 v2 已允许的路径），不发任何运动命令 |
| `WAM_ACTIVE`（快通道段） | **命令闸** | 对模型提议做 PASS/SLOW/STOP 裁决后经 Arbiter 发**平台运控 Twist**；这是唯一的闭环作用域 |
| 其余状态 | 硬 dry-run | 零输出 |

```text
传感器 → episode 落盘/QA → 异步边端推理 → RiskProposal
                                       ↓
             ┌── MISSION_NAV：观察者（告警/任务级停止）
ProposalGate ┤
             └── WAM_ACTIVE：命令闸 → DogControlArbiter.move() → 平台运控 WS（Twist）
```

> **v3.5 变更**：命令出口由宇树 DDS `SportClient.Move` 改为**平台运控 WebSocket**（§1.6-A1）。
> Arbiter/Gate 的状态机与不变量 **I1–I10 不变**，只换后端 transport；
> 这是有意的设计——安全语义不应随载体变化。

### 0.5 双轴降级与弱指令（v3.6）

现场「弱网／断网」常被说成一件事。本方案拆成两轴，**禁止互相冒充验收**：

| 轴 | 回答的问题 | 典型手段 | 本仓库位置 |
|---|---|---|---|
| **A · 通信退化** | 指令／状态**传不传得到** | 自组网（端侧互发）、无人机中继（云→空→地）、多链路、弱网降载 | 传输层；接口见待建 §1.7；09-14 前以契约与试验条件为主 |
| **B · 端侧计算故障** | 传到／未传到之后，本体**该不该动、会不会重复危险动作** | 本地推理降级、ProposalGate、检查点、TTL／幂等／session fencing、安全停 | Gate／Arbiter／runtime；D5 骨架起强制 |

**弱指令（本方案定义，与业务侧对齐）**

- **弱＝控制权弱**，不是「发得慢」或「包很小」。
- 远端、邻机、云端编排只允许下发 **任务级高层意图**（示例语义：去点／跟随／暂停／返航／进入安全保持）——即 L3 及以上意图信封。
- **禁止**经弱网远链路闭环下发连续速度、姿态、力矩（L0／L1）；此类必须由本体控制器 + Gate 在本地完成。
- 与铁律同构：外部源（云／邻机／模型）只出提议或意图；**执行权永远在独立哨兵／仲裁层**。

**弱指令信封（最小字段，实现前冻结）**

```text
WeakIntent{
  mission_id, epoch, seq, ttl_ms, source, intent, args,
  ack_required, idempotency_key, issued_t_mono_ms
}
```

规则：过期（TTL）拒绝；跨 `epoch`／旧 `seq` 拒绝；同一 `idempotency_key` 不得导致重复危险动作；重连后先对账再接受新意图。

**验收分层（写进试验报告抬头）**

1. 通信条件：自组网／中继／全断／重连时延、丢包——只作**试验条件**。  
2. 控制结果：Gate 裁决、危险动作计数、是否进入 `SAFE_HOLD`——才是**成功标准**。  
3. 「链路恢复成功」单独成行，**不得**写入「部署闭环通过」。

**09-14 前边界**：不新开「组网项目」阶段；允许在 D1 盘点中记录现场是否具备自组网／中继／Jetson；D5 骨架的故障注入子集必须覆盖 §0.5 三类通信硬故障（可用模拟断链，不必真飞中继）。

**由此确定的三条口径**

1. **快通道的承载者未定。** 「连续速度 10–50Hz + deadman + 实际速度回读」这组能力，现在只可能由集成商的运控接口提供。该接口的**契约等级未知**——只拿到调用示例不足以判断，必须拿到：最高下发频率、端到端时延、停发后归零时间、能否读回实际速度、错误码、权属交接机制。这五项决定 D7 是否成立（见附录 B 的问询清单）。
2. ~~**我们目前没有合法的运动级急停。**~~ **已于 2026-08-10 闭合**：运控 WS 的零速指令即常规刹车，
   叠加平台 deadman 0.5 s 自停（§1.6-A2/A3）。⚠️ 但「软件急停」在 B1/B2 上**只是电机断电、狗会塌**，
   不是优雅停车——现场规程须写明优先零速（§5 残余风险 2）。
3. **到点判定改为双源交叉校验**（优于原设计，非简单替换）：
   - 主证据：MQ 推送（低时延）；
   - 兜底：`PollCache` 轮询 `getCurrentByRobotId`（补丢消息、乱序、MQ 断连）；
   - 两者均不可用 → `nav_status_unknown` **fail-closed**，不得默认「已到达」。
   - `TopseeNav` 已有「到点三态」抽象，MQ 是**给同一输出增加证据源**，不是重写。
   - ⚠️ `instruction.complete == true` **不等于成功到达**（失败/取消/超时同样可能置真）。没有结果码前禁止直接发 `DOG_ARRIVED`。

**未知项（禁止假设，未拿到书面契约前不得写实现）**：运控接口的五项契约；MQ 的 broker 地址/协议/认证/QoS；`robotNum` 与 `robotId` 的映射；MQ 消息与本次 `sendNavigate(pointsId)` 的唯一关联键。

> **§1.5 时效说明**：其中「未知项」已于 2026-08-10 大部分闭合，见 §1.6。
> V1 的「不建议直连 DDS」结论**仍然有效**，但原因升级：除政策外，狗侧内网从我方位置**物理不可路由**（§1.6-C1）。

```python
# adapters/proposal_types.py（新文件，模型进程与 Gate 共享的唯一契约）
@dataclass(frozen=True)
class RiskProposal:
    session_id: int           # 模型进程启动时刻 epoch_ms（防跨 session 重放）
    seq: int                  # session 内单调递增
    obs_t_mono_ms: int        # 该提议依据的观测时间戳（单调钟）
    issued_t_mono_ms: int     # 提议发出时刻
    risk_score: float         # [0,1]
    action: str               # "pass" | "slow" | "stop"
    dvx: float; dvy: float; dvyaw: float   # 机体系速度修正建议，Gate 侧再次钳位
    model_ver: str            # 对应 artifacts/student_<ver>

@dataclass(frozen=True)
class GateVerdict:
    proposal_session: int
    proposal_seq: int
    decision: str             # "PASS" | "SLOW" | "STOP" | "DROP"
    reason: str               # ok/stale_obs/ttl_expired/nan/bounds/accel/jerk/
                              # model_dead/model_silent/dds_stale/thermal/battery/
                              # lease_invalid/out_of_scope(非WAM_ACTIVE)/dry_run/replay
    applied_vx: float; applied_vy: float; applied_vyaw: float  # 实发命令（dry-run 恒 0）
    t_mono_ms: int
```

- 传输：UDS datagram，单向 模型→Gate；Gate 不回包（模型不依赖 Gate 存活）；
- **单位/坐标系（v3.5 修订）**：提议侧全部 SI、**机体系**，`dvx/dvy/dvyaw` 语义等同 ROS Twist 的
  `linear.x` / `linear.y` / `angular.z`，由 Arbiter 后端映射到平台运控 WS 的 `twist` 字段；
- **命令周期硬约束**：平台 deadman = 0.5 s（§1.6-A2）。`WAM_ACTIVE` 期间 Arbiter 必须以
  **200 ms 周期持续下发**（含零速保持），断流即被平台判停。此周期是安全参数，
  放宽需与 `SpeedLimits` 同级的 PR 流程；
- **角度换算隔离**：平台 `position.th` 为「右为 0、顺时针为正」的弧度（§1.6-A5），
  与 ROS 约定相反。**禁止直接透传**——须经单一转换函数并配单元测试；
- **禁用能力**：B2 无身高/步态控制（§1.6-A8），`RiskProposal` 不得新增相关字段；
- `FORBIDDEN_KEYS` 红线不变：位姿/点云/图像永不进 `mission_brain.events`；
- 配置唯一入口：`configs/dog/topsee.json`（平台回填）、`configs/dog/gate.json`（阈值）、`configs/dog/dataset_split.json`（数据切分）；
- 测试入口：`tests/test_dog_runtime.py` / `test_edge_bench.py` / `test_episode_qa.py` / `test_proposal_gate.py` / `test_single_exit.py`；全套 `python -m pytest tests/ -q` 必须全绿后才许提 PR。

## 5. 安全论证（fail-safe 摘要）

> **v3.5 重写**：命令载体改为平台运控 WS，且集成商给出 deadman = 0.5 s 官方口径（§1.6-A2）。
> 安全论证的骨架因此从「软件侧独撑」变为「软件侧 + 平台侧超时」双层，但**新增两条一级缺口**（§1.6-B1/B2）。

| 失效 | 行为 | 兜底 | 强度 |
|---|---|---|---|
| 模型进程死/假死 | Gate ≤100 ms 检出 → HOLD/零速 | Gate 独立于模型进程 | ✅ 已验证（软件） |
| Gate 进程死 | Arbiter 命令看门狗超时 → 零速（I5）；`WAM_ACTIVE` 租约 TTL 过期 → `SAFE_HOLD` | **平台 deadman 0.5 s** 兜底：Arbiter 停发即自停 | 🟡 有官方口径，**待 E4-C② 实测复核** |
| Arbiter / 我方整机死 | 指令停发 → 触发平台 deadman → 0.5 s 内自停 | 实体急停 / 遥控器 | 🟡 **取决于 U1**：若 deadman 由上位机进程实现，而上位机与我方进程同机，则同一故障域，**该兜底不成立**。U1 未答前按「不成立」处置 |
| 上位机（平台一体机）死 | 🔴 运控通道整体消失，狗停留在最后一条指令的行为 | **仅实体急停 / 遥控器** | 🔴 无软件兜底。现场双人 + 实体急停在手，**不可缺席** |
| STOP 不确认 | `safe_hold()` 后连续 2 帧 MQ `speed > 0.1 m/s`（≈1 s）→ 升级软件急停 + 现场告警 | MQ `service_robot_status.speed` 提供速度回读（§1.6-C2） | 🟡 可闭环，但**确认延迟 ≥1 s**（2 Hz 遥测的物理下限） |
| 现场人员与我方**同时下发** | 🔴 平台当前版本**不校验控制权**（§1.6-B1），双头指令直接叠加/竞争 | 仅靠现场规程（单一操作端 + 口头交接） | 🔴 **行政控制，安全等级最低**。D7 准入必须先实测封堵，见 §2 E4-C③ |
| 速度提议越界 | Gate + `SpeedLimits` 分轴钳位 | 🔴 **服务端无限幅**（§1.6-B2），无第二道 | 🔴 **唯一防线**。红线 §6.3 升级 |
| 日志 I/O 阻塞 | 异步有界队列，丢日志不丢命令 | 磁盘水位 <10% 停录制 | ✅ |
| 电量/温度未知 | fail-closed，拒绝放行 | D0 Q4 已修 | ✅ |
| 中继掉线／自组网邻居失联（v3.6） | 停止接受新弱意图；连续控制不受远端影响；超时→`SAFE_HOLD` | 本体 Gate + 意图 TTL／epoch | 🟡 契约已定义，D5 注入待实现 |
| 全链路断开（v3.6） | 远端不可达；本体按本地策略保持或安全停，**禁止**等待云端才决策 | 本地哨兵 + 平台 deadman | 🟡 与「上位机死」叠加时仍依赖实体急停 |
| 端侧重启后重连（v3.6） | 先安全态与检查点对账，再接受新 `WeakIntent`；旧 seq／跨 epoch／同 idempotency 重放全部拒绝 | session fencing + 幂等键 | 🟡 D5 骨架必须覆盖；「又连上了」≠验收通过 |

**残余风险（写入 D7 安全审批材料，不得省略）**

1. **遥测 2 Hz 限制闭环带宽**（§1.6-A7）。状态滞后最坏 500 ms，叠加 200 ms 指令周期，
   闭环反应时间下限约 0.7 s。**D7 走廊段速度上限须据此反推**，不得沿用 `SpeedLimits` 默认值。
   平台升到 10 Hz 之前，这是硬上限。
2. **无整机断电接口**（§1.6-A3）。软件急停仅电机断电，狗会失去支撑塌落——
   对 60 kg 机身，这本身是伤害源。**软件急停不是安全动作，是损失控制手段**，
   现场规程必须写明「优先零速停车，急停仅限已发生危险」。
3. **`/edg` 为明文 WebSocket 且服务端无限幅**。任何接入客户网络的设备都可越过我方 Gate 直发运控。
   属客户网络治理范围，我方不触碰，但须**书面提示客户**。
4. **协议无兼容承诺**（§1.6-U3）。平台升级可能静默改掉运控协议。
   D7 前需约定变更通知渠道，否则每次升级都要重跑 E4-C。

## 6. 红线（违者回退，无豁免）

1. **模型永不直接发运动命令**——唯一出口＝ProposalGate（`test_single_exit.py` 机械保证）；解锁走 D5 三件套 PR 流程。
2. **位姿只进 WAM 落盘通道**，绝不进 `mission_brain.events`（`test_no_pose_leaks_into_events` 守护）。
3. **速度安全盒是唯一防线**（v3.5 升级）。服务端确认不做限幅（§1.6-B2），`SpeedLimits` 之外**没有第二道**。
   放宽必须显式 PR + 双人确认 + 现场复测；D7 期间反向收紧。任何绕过 `SpeedLimits` 直发 `/edg` 的代码路径＝立即回退。
4. **控制权不是安全机制**（v3.5 新增）。平台当前版本运控不校验控制权（§1.6-B1）。
   我方必须主动抢控以前向兼容，但**禁止**在设计中把「持有控制权」当作「他人无法下发」的保证；
   任何依赖该假设的安全论证一律判无效。
4. **i5 平台机绝不动**；Jetson 不擅自升 JetPack。
5. **禁止伪造人工输入**：气体台账、`ack_confidence` 填假值＝拆安全门禁。
6. **QA 不过的数据禁止训练**，无豁免通道。
7. `MISSION_NAV` 期间 Gate 只做观察者与任务级停止，**永不发 Move**（I3/I4 延续）。
8. **本仓库资产合规**：本项目代码、数据、配置、模型、checkpoint、日志及公司硬件采集结果不得进入无关仓库、个人设备或未经批准的外部系统；外部资产也不得在来源、许可和审批不明确时混入本仓库。仅可复用许可证允许且来源可追溯的公开方法与指标定义（见 §0.3 / §0.4）。

## 7. Kill criteria

- 任一工作流两周无可运行工件+原始测量 → 停该工作流。
- 学生模型两轮优化仍超 P95 预算或 INT8 掉点超限 → 换模型/再蒸馏，**不靠买 AGX 解决**。
- E1/E3/E4 阻塞闭环超两周 → 狗停在影子模式（影子本身已是可交付成果），闭环验证转仿真/无人机床。
- Gate 出现一次危险提议放行或一次 STOP 未闭环确认 → 闭环资格清零，重跑 D5 全量注入。
- 第三方平台需长期逆向私有 API 才能拿基本状态 → 平台降级为 topo 命令源，不再深度耦合。
- **视频取流因端口收敛不可得且无替代路径**（§1.6-F3）→ D2b/D3 数据采集停摆，
  整条「教师→学生」产线失去输入。此时不是调方案，是**停项目并上报**——
  没有数据的部署闭环不存在。

## 8. 与无人机/服务器的关系（一段话）

无人机栈冻结新功能，仅作「近端伴飞边端」故障注入床：`edge_bench` / `episode_qa`（各自 schema）/ Gate 降级逻辑必须在 Tello 链路复用验证；一旦需要 Tello 专属新框架即砍。服务器＝教师与离线评测环境：负责伪标签、蒸馏、批量回归，并产出可复现、版本化、可审计的离线工件；不再出现在任何实时控制路径。
