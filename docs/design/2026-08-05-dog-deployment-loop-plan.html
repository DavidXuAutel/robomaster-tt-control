一句话：项目重心从「把狗接进任务编排」升级为「部署闭环」—— 服务器当老师 → 边端跑学生模型 → 量化评测（时延/内存/功耗/成功率）→ 独立故障哨兵 → 影子部署 → 受限闭环。

核心铁律：模型只出提议，执行权永远在独立哨兵/仲裁层手里；模型进程崩溃，狗必须能停。

0. 为什么改 & Gate 两种作用域

改造理由：①远程 GPU（cloudflared 隧道 4090）在实时控制链里＝延迟污染+单点故障，只该做老师；②「记录了数据」≠「数据可训练」，丢帧/时钟漂移目前没人自动查；③让生成式模型直接控 60kg 真狗是错误顺序。

Gate 的两种作用域（解决 v3.0 的架构矛盾）

现有仲裁层规定：平台导航期间（MISSION_NAV）禁止发任何 DDS Move； 平台又没有连续速度接口。所以「在原生导航上叠加减速」不可实现，明确放弃。哨兵（ProposalGate）按仲裁状态分两种角色：

仲裁状态Gate 角色能做什么
MISSION_NAV（平台导航中）观察者只记录裁决+告警；风险持续超阈只能走任务级停止（平台 stopTask，这是 v2 已允许的路径），不发 Move
WAM_ACTIVE（快通道段）命令闸对模型提议裁决 PASS/SLOW/STOP，经仲裁层发 Move——唯一的闭环作用域
其余状态硬 dry-run零输出
传感器 → episode 落盘/QA → 异步边端推理 → RiskProposal
                                       ↓
             ┌── MISSION_NAV：观察者（告警 / 任务级停止）
ProposalGate ┤
             └── WAM_ACTIVE：命令闸 → Arbiter.move() → DDS Move

3. 阶段计划 D0–D8（总计约 12–14 周）

工期口径：单工程师 + 每周 2–3 天现场折算。评审判定原 6 周估计不诚实，已改。厂商答复、场地审批、采购属外部等待，单列不计入（见 md 附录 B）。每阶段交付＝代码+测试+一份 artifacts/ 报告，无报告不算完成。

D0 地基修复与生产接线（第 1–2 周）★评审必修

  • 实现真实 DDS subscriber（位姿 /sportmodestate、本体 /lowstate；>500ms 无样本判断流）；
  • 新建 runtime/dog_runtime.py：唯一进程编排入口（装配全部组件+健康检查+日志轮转+磁盘水位）；
  • abort 链路闭合（abort 必须触发仲裁层 force_release()）；
  • Q3/Q4 修复：置信度校验+持久审计；电量门禁 fail-closed；
  • 配置落位 configs/dog/topsee.json（E 回填六项唯一入口）。

验收：新增测试全绿；真实订阅在狗侧网络连跑 10 分钟无断流（需现场；未排期则先交离线全绿+现场清单）。

D1 现机盘点 + 只读探针 + 评测 harness（第 2–3 周）

  • artifacts/b2_inventory.json：狗上到底有几台计算机、有没有 Jetson、系统版本、视频流地址、网络拓扑——宇树官方标配是 i5+i7 双 x86 不带 Jetson，本机被拓普视改装过，必须盘点不许假设；
  • 探针只读集（E0/E2/E5–E10）跑完回填配置；
  • tools/edge_bench.py 评测工具：任意模型+任意输入源 → JSON 报告（P50/P95/P99 时延、FPS、内存、温度、功耗、丢帧、降频）。计时边界写死：帧解码完成→推理返回，预热 100 帧不计。

验收：i7 与 Jetson（若有）各连跑 30 分钟零崩溃；周末给出算力决策（现有 NX / 增购 NX 16GB / 暂用 i7）。

D2a 狗版录制器 + 统一质检/回放（离线，第 3–4 周）

  • adapters/dog_recorder.py：深度帧主时钟落盘（v2 §6 规格）；深度不可得自动降级 RGB 主时钟并在 meta 声明；schema v2，与无人机旧格式不做兼容层；
  • tools/episode_qa.py：机器可读质检清单，指标全部有公式——时钟单调性、跨流对齐误差（P99≤50ms）、动作标签延迟（真值＝命令下发时刻）、缺帧率（<1%）、地图跳变；继承 v2 §6.7 全部旧门槛；
  • tools/episode_replay.py：按原时序回放喂任意推理后端，确定性可校验。

验收：100 个注入损坏全检出零漏报；QA 失败的数据禁止进训练集，无人工豁免通道。

D2b 录制真机验收（第 4–5 周，半周现场）

真实视频+真实 DDS 位姿录 ≥5 段（每段 ≥120s），QA 全过；深度通道可用性给出正式结论。

D3 数据采集战役（第 5–6 周，现场）★新增

  • ≥6 条差异化路线（直行/转弯/坡道/窄道/动态行人区/弱纹理区）×各 ≥5 遍；
  • ≥40 段 QA 通过的 episode；训练/验证/测试按路线切分（4/1/1）防泄漏；
  • 危险事件类别草案（供 D6 标注协议）。

D4 教师→学生模型产线（第 6–8 周）

  • 4090 教师（Depth Anything V2）产伪标签；可通行性规则写死并版本化：前方 1.5s 走廊最小障碍距离 → 三档（slow<2.0m、stop<1.0m 初值）；
  • 学生模型（轻量级）：输入前向 RGB+速度 → 输出风险分、三档动作、速度修正（训练期即钳位在安全盒内）；
  • 测试真值：≥500 帧人工复核标签（双人标注+仲裁），不拿老师自己当裁判；
  • 导出链 ONNX→TensorRT，引擎必须在目标 Jetson 上构建（服务器编的不可移植）；产物打包带数据版本+git SHA+依赖锁。

验收：人工真值集上 stop 二分类 AUC ≥0.90、档位准确率 ≥85%；边端 60 分钟连跑 P95≤80ms、内存≤12GB、功耗≤25W；INT8 相对 FP16 掉点≤2pp。

D5 ProposalGate 哨兵（第 6–9 周，与 D4 并行）

  • 独立进程 50Hz 循环；模型经 UDS 单向发提议（带 session_id+seq，防重放/乱序）；
  • 检查项全部有阈值且进 configs/dog/gate.json：提议 TTL≤200ms、观测年龄≤300ms、速度盒、加速度≤1.0m/s²、jerk≤3.0m/s³、NaN 拒绝、模型静默>500ms→HOLD、DDS 断流、温度>85℃、电量<25%（fail-closed）；
  • SLOW 融合算术唯一定义：v = clamp(v名义+Δv, 安全盒) × (1−risk)，再过加速度/jerk 限幅；
  • 唯一命令出口机械保证：发令函数加 gate_token 私钥参数 + 静态扫描测试 test_single_exit.py，全仓库只允许 Gate 调用发令；
  • 裁决与实发命令双落盘（异步有界队列，丢日志不丢命令）；
  • dry-run 硬锁解锁流程：一个显式 PR 同时改运行时传值 + 勾选解锁清单（E1/E3/E4 结论+影子准入报告+双人签名）+ CI 校验，三缺一 CI 红。

验收：≥10,000 次故障注入——危险提议放行数＝0、检出≤100ms、计划零速≤250ms、干净数据误 STOP<1%（分母＝裁决 tick 数）。

D6 影子部署（第 9–11 周）

  • 模型实时提议、Gate 实时裁决（dry-run 硬锁），三路同录：裁决流 / 平台导航状态 / 人工干预打点；
  • 标注协议写死：10s 不重叠窗口、危险类别定稿、双人独立标注+第三人仲裁、时间交叠≥50% 记命中；
  • 验收：≥2 小时 ≥10 路线段；可用率≥99.5%（定义：每 tick 有裁决且输入年龄达标的占比）；≥300 个窗口上危险召回≥95%、误停≤5%（分母＝无危险窗口数）；四项全绿出《闭环准入报告》。
  • 诚实声明 本阶段不做命令级对照——那需要 E1 与平台速度接口，做不到就不承诺。

D7 受限闭环 A/B（第 11–13 周 + 审批等待，硬门禁）

准入六条缺一不可：E1 结论、E3 演练≥3 次、E4 四步全过、影子准入报告全绿、解锁 PR 合入、现场安全审批（封闭场地/实体急停/安全盒收紧至 0.5/0.3/0.5/电量>25%/双人在场）。

  • A 臂＝平台 teach-and-repeat 原生导航走全程；
  • B 臂＝同路线拆出 1 段 ≤20m 的 WAM_ACTIVE 走廊段：模型提议→Gate 裁决→仲裁发 Move；走廊两侧虚拟墙+实体围栏——闭环只发生在快通道段，不违反既有互斥契约；
  • 配对设计 ≥60 次（30 对，顺序随机）；成功/干预/越界全部有操作定义；
  • 验收：零越界（一次即终止回 D5）；B 臂成功率≥90% 且干预率相对下降≥20%，90% 置信区间下界>0 才算证实。

D8 复盘与交接（第 13–14 周）

全链路指标汇总、欠账滚动清单、下一期建议（只写清单不自动立项）。

4. 接口契约（摘要）

RiskProposal:  session_id, seq, obs_t_mono_ms, issued_t_mono_ms,
               risk_score[0,1], action(pass|slow|stop),
               dvx dvy dvyaw(机体系,SI), model_ver
GateVerdict:   proposal_session, proposal_seq,
               decision(PASS|SLOW|STOP|DROP), reason(枚举),
               applied_vx/vy/vyaw(实发命令,dry-run恒0), t_mono_ms
  • 传输：UDS datagram 单向（模型→Gate），Gate 不回包——模型不依赖 Gate 存活；
  • 位姿/点云/图像永不进事件总线（既有红线延续）；
  • 配置唯一入口：configs/dog/topsee.json / gate.json / dataset_split.json；
  • 测试入口：test_dog_runtime / test_edge_bench / test_episode_qa / test_proposal_gate / test_single_exit。

6. 红线与 Kill criteria

红线（违者回退，无豁免）
  1. 模型永不直接发 Move——唯一出口＝Gate（静态扫描机械保证）；解锁走三件套 PR；
  2. DDS 位姿只进落盘通道，绝不进事件总线；
  3. 速度安全盒由我们实现（遥控器软限位在直控路径不生效）；放宽须显式 PR+双人确认；
  4. i5 平台机绝不动；Jetson 不擅自升 JetPack；
  5. 禁止伪造人工输入（气体台账/置信度）＝拆安全门禁；
  6. QA 不过的数据禁止训练，无豁免通道；
  7. 平台导航期间 Gate 只做观察者与任务级停止，永不发 Move。
  • 任一工作流两周无可运行工件+原始测量 → 停；
  • 学生模型两轮优化仍超预算 → 换模型/再蒸馏，不靠买 AGX 解决；
  • E1/E3/E4 阻塞超两周 → 停在影子模式（影子本身已是可交付成果）；
  • Gate 一次危险放行或一次 STOP 未确认 → 闭环资格清零重跑全量注入；
  • 平台要长期逆向私有 API → 降级为拓扑命令源，不再深耦合。
