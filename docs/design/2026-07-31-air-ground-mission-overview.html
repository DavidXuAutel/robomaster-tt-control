Volkswagen Demo · Air–Ground Collaboration

空地协同演示方案总览

无人机先侦察发现目标 → 中枢编排派任务 → 机器狗到点重找并完成气检。共享的是「区域任务地图」，不是同一张稠密点云。

G0 骨架已合入 G1–G2 设计待确认开工 2026-07-31 硬件：Tello / 道通 4T / 宇树狗 / Mac / A26125

1. 一句话架构

侦察角色：飞机在空中巡逻、认区域、找标记物，负责「发现」而不是给狗发精确坐标。 （无人机）找目标 · 任务大脑：像交通指挥，按状态机决定下一步派谁干什么；不直接拧飞机摇杆、不替狗避障。 派单 · 机器狗用自己的 激光雷达即时定位与建图：狗用激光扫周围，在自己地图里知道身在何处、怎么走到路点。 到点干活。

共享 不共享毫米级点云，只共享「区域X → 狗该去哪个路点 / 飞机飞哪段 / 门口贴哪个标签」这种任务层对照表。 ； 物体 A = 高对比色板或 AprilTag 一类人工标记，稳定好检，适合演示；不是开放词汇「任意工业零件识别」。 。

2. 端到端剧本（演示在干什么）

  1. 开任务：Brain 收到 mission.start（目标标签、候选区域、截止时间）。
  2. 空中侦察：无人机 状态：飞机正在指定区域巡航找目标。 ，复用现有 wander/巡航能力。
  3. 发现并确认区域：同时看到区域锚点 + 物体 A → 发 drone.target_found（带 region、置信度、证据图路径）。
  4. 派狗：Brain 查语义地图，把 region 换成狗地图里的 预先在狗的 SLAM 地图里标好的路点 ID，例如区域入口观察点；不是飞机估出来的 XYZ 坐标。 ，发 dog.inspect。
  5. 狗到点重找：导航到集结点 → dog.arrived → 用机载相机再找一遍物体 A → dog.target_found。
  6. 气检动作：gas.sample → 读数回传 gas.completed → mission.completed。
  7. 失败安全：超时 / 断链 / 人工中止 → 安全失败终态：任务明确失败并留证据，同时要求飞机悬停/降落、狗 cancel 停步，不能假装还在执行。 。

4. 语义地图长什么样？

不是激光点云，也不是一张大家都对齐的 3D 网格；而是一份版本化 JSON： 「区域名 → 狗去哪、飞机飞哪段、门口贴哪个锚点」。

场地可以这样理解：

场地
├── region_x  演示区（气源/阀门模拟）
│   ├── dog_goal_id     = wp_region_x_staging   ← 狗 SLAM 里预标的集结点
│   ├── drone_route_id  = route_region_x_scout  ← 飞机巡航段
│   └── anchor_ids      = TAG-0 / AX-01          ← 门口锚点
└── region_y  备用区
    ├── wp_region_y_staging
    ├── route_region_y_scout
    └── TAG-1 / AX-02
Why · 为什么共享这个而不是共享 SLAM 工业巡检狗本来就会在自己的 LiDAR 地图里设路点；飞机（尤其 Tello）很难提供可靠全局米制坐标。 业界空地协作前沿（如 Kumar Robotics 的 Semantic Persistent Occupancy Map：空中建语义正射图、再与地面机器人对齐的研究系统；理念是「共享语义层」，不是硬融同一张稠密点云。 ）也强调语义层协作。 我们的 v1 与这条叙事同构，但工程上只做「任务拓扑表」，不搬整套研究系统——演示可靠优先。

5. 关键设计点：为什么这样选

5.1 狗吃 SLAM，飞机吃侦察 —— 不融同一张稠密图

对照共享稠密 SLAM

  • 空对地视角差大，点云/视觉难对齐
  • Tello 无可靠全局定位；标定与漂移吃工期
  • 任一端地图坏了，整条链路假坐标派错狗

推荐语义/拓扑任务地图

  • 狗地图权威（米制导航本职）
  • 飞机只报 region_id + 锚点证据
  • 到点后狗必须重新发现 A（不信飞机坐标）

参考叙事：SPOMP / lang-air-ground-teaming（语义协作）；v1 拒绝把它们整仓搬进演示。

5.2 MissionBrain = 编排 FSM，不是 WAM

World-Action Model：看图直接出飞行动作的策略模型。适合作为 Scout/狗内部的「怎么飞/怎么走」插件，不适合当多机任务调度中枢。 回答「这一帧该怎么动」；MissionBrain 回答「现在该谁上场、超时怎么办、能不能再派一次」。 混在一起会导致：模型抖一下就重复派狗、中止语义不清、无法做契约回放测试。

设计收益 幂等 同一条命令即使因网络重传收到两次，也只执行一次。靠 event_id 去重 + 「已经派过狗」标志位。 派单、阶段超时、abort 可测；WAM 以后可插在 Scout/Dog 策略缝，不替代 Brain。

5.3 事件契约：只传任务事实，禁止重载荷

总线只走 drone.target_found / dog.inspect / gas.completed 等轻事件。 禁止塞全局 pose、点云、实时视频——那些该走专用通道或本地落盘（evidence_uri）。

Why 参考工业多机系统的「命令/事件面与感知面分离」：调度通道要小、可日志、可回放； 视频和点云一旦进总线，带宽与假坐标风险一起爆。

5.4 Tello 沙箱 → 道通承接大场

Tello：室内算法与契约验证快、成本低。
道通 4T：大场地 / 室外可选 实时动态差分定位：用基站或网络修正 GPS，室外可达厘米级；室内几乎没用。 、航点任务更接近演示飞机。 两边对齐同一 Scout 契约，避免「Tello 接口变成生产接口」。

6. 三项关键选择（白话说明）

① 标记物怎么贴：单点蓝锚 + 红物体；多区强制 AprilTag

在干什么：规定「门口标签」和「物体 A」长什么样，好让相机稳定认出来。

  • 物体 A：红色标记板（演示目标）。
  • 区域锚点：证明飞机「在哪个区」。只测一个区时，蓝色板够用；两个区以上必须用不同 ID 的 一种专为机器人定位设计的二维码族（常用 tag36h11）。比普通 QR 更适合当「我是几号锚点」的定位原语，检出稳、可算相对姿态。 。
Why · 为何不能两区都贴同一种蓝板 颜色检测只能回答「看见蓝色了」，不能回答「这是区 X 还是区 Y」。 若强行用同色区分，系统会把「当前正在搜的区」贴到色块上——这是自证循环，会把狗派错路点。 AprilTag 每个 ID 唯一，才能做多区。

② 本迭代不做 MQTT，先用进程内总线

在干什么：决定「飞机 / Brain / 狗」之间事件怎么传。

  • 现在（本迭代）：同一程序里的 进程内事件总线：模块之间在内存里发布/订阅事件，适合本机联调与自动化测试，不经过网络。 ——适合脚本回放、单机测契约。
  • 以后联调：再上 一种轻量发布/订阅消息协议，常用于物联网与机器人跨设备通信。适合 Mac、服务器、狗工控机不在同一进程时传任务事件。 或 WebSocket，把同一套事件搬到跨电脑。
Why · 为何先不做 MQTT 当前还有 abort 广播、串行侦察等控制面缺口；一上网络会把「状态机绿、真狗还在走」这类 bug 放大到三台机器。 工程顺序：先把进程内 supervisor 做对（同一 abort 必须同时到 Brain + 狗 cancel），再换传输层。

③ 合成契约 与 真机录制 分开记账

在干什么：规定「怎样才算 G2（无人机单独）验收过了」，防止假绿。

合成契约与真机录制双账本
账本测什么能对外说什么
用程序生成的图片/参数化场景，专门验证：事件字段对不对、会不会误派狗、重复消息会不会派两次。 软件契约、状态机、零误派狗 「契约与逻辑 20/20」——不能说真机已过
用 Tello 在真实场地拍下的小数据集（正例、只有锚点、只有红板、暗光、模糊等），验证检测在真实画面上是否靠谱。 真实光照/模糊/反光下的检出 「真机感知 N/N」——这才算真机 G2
Why · 参考数据工程习惯 合成数据擅长覆盖边界（乱序、重复、低置信）；实拍数据才代表部署分布。 混成一个「20/20」分数，等于让检测器自己出题自己答——演示现场光照一变就会穿帮。

7. 分阶段怎么验收（G0–G5）

分阶段验收门 G0 到 G5
门内容状态意图
G0契约回放：乱序/重复/abort 不炸自动化已齐
G1狗单独：同路点 10 次到点 + 安全停先 FakeNav，型号确认后挂真 SDK
G2机单独：合成契约 + 真机录制双账本；Autel 尖刺设计已审，待开工
G3交接：狗到点后独立重找 A，10/10分测后
G4气检：有效采样窗；断传感器/标定过期显式失败分测后
G5大场端到端 10 连跑（含 NOT_FOUND / 断链 / abort）室外联调
场地节奏 室内：单点测 G0–G4 逻辑与感知。室外：G5 集成；演示飞机倾向道通 4T，Tello 继续当侦察沙箱。

v1 明确不做

Rejected 共享稠密 SLAM · 跨视角 视觉位置识别：靠图像问「我在哪」。空对地视角差极大时很脆，不宜作 v1 依赖。 依赖 · Hydra 级场景图 · LLM 任务规划 · Wi‑Fi RTT · WAM 替代 MissionBrain · UWB（可作 v2）

8. 术语速查（正文虚线词可点按 / 悬停）

LiDAR
激光雷达：扫周围得距离点云，狗用来建图、定位、避障。
SLAM
边走边建图并定位；本方案里狗侧是权威米制地图。
工控机 / 机载算力
狗身上跑导航与检测的电脑（照片里的 Legion 一类）。
RTK
室外高精度 GPS 修正；室内基本无用。
AprilTag
机器人定位用的标签族；多区域时用来唯一标识入口。
FSM
有限状态机：任务阶段清晰、可测、可超时。
MissionBrain
任务编排中枢：派谁、何时中止；不下杆量。
Scout
空中侦察代理：发现 + 报区域，不指挥狗行走。
dog_goal_id
狗地图里预标路点；派狗只许用这个，不许用飞机 XYZ。
EventBus / MQTT
前者本机内存传事件；后者跨设备消息协议（联调再上）。
WAM
观察→动作策略；可做插件，不替代编排。
SPOMP
空地语义地图协作研究路线；我们借叙事，不搬整仓。
G0–G5
分阶段验收门：从无硬件契约到大场 10 连跑。
幂等 / abort
重复消息不重复执行；中止必须落到狗 cancel 与飞机停。
