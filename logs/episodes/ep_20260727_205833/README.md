## 对齐保证

**`video.mp4` 的第 N 帧 ↔ `frames.csv` 的第 N 行**，严格 1:1，已校验零错位
（视频 2355 帧 = CSV 2355 行）。

`frames.csv` 的 `video_frame` 列为视频帧号（从 0 起），`frame_id` 从 1 起，
恒满足 `video_frame == frame_id - 1`。

视频容器标称 10 fps，但真实时刻以 `t_mono_ms`（单调时钟，从 0 起的毫秒）为准。
无线链路抖动会导致帧间隔非严格等距，需要精确时序时请用 `t_mono_ms`。

## 操控动作列（核心）

四轴杆量，取值范围 **−100 ~ +100**，语义与 Tello SDK `rc` 指令一致：

| 列 | 含义 | 正方向 | 本回合实测范围 | 非零帧 |
|---|---|---|---|---|
| `act_roll` | 横滚（左右平移） | 右 | 0 ~ +10 | 2129 |
| `act_pitch` | 俯仰（前后移动） | 前 | −18 ~ +25 | 606 |
| `act_throttle` | 油门（升降） | 上 | 恒为 0 | 0 |
| `act_yaw` | 偏航（原地转向） | 顺时针 | −25 ~ +25 | 2281 |

**2355 帧中 2333 帧（99%）有非零动作输出。**

环绕动作的典型组合是 `roll`（切向横移，画圆的线速度）与 `yaw`（转头保持椅子居中）
同时输出，`pitch` 仅在需要修正环绕半径时介入——这与随机漫游那份
（`roll` 恒 0、`pitch`/`yaw` 交替）是两种截然不同的动作模式。

### `ctrl_state`：动作来源与实时遥测

| 前缀 | 帧数 | 含义 |
|---|---|---|
| `ORBIT` | 2310 | 自动 · 环绕椅子飞行（98%） |
| `CRUISE` | 22 | 自动 · 锁定目标前的直线接近 |
| `HOVER` | 22 | 悬停 / 未挂载自动模式 |
| `pre_orbit` | 1 | 进入环绕的过渡帧 |

**本回合无人工接管**（`frames_manual: 0`），全部动作由自动策略产生。

注意 `ORBIT` 帧的 `ctrl_state` 不是单纯枚举值，而是附带了实时控制遥测的完整字符串：

```
ORBIT pos+0.15 orbit L0.24 M0.50 R0.29 tn0.66 yaw+12 pit+0 rc(4, 0, 0, 10)
```

按空格取第一段即为状态名。各字段含义：`pos` 椅子在画面中的水平偏移
（−1 最左 / 0 正中 / +1 最右）；`L/M/R` 左中右三区近度；`tn` 目标距离读数
（越大越近）；`yaw` `pit` `rc` 为控制器输出。**筛选环绕段用
`ctrl_state.startswith('ORBIT')`。**
